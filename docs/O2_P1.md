# O2 P1: memory, context and provider services

## Rollout and compatibility

P1 extends the P0 SQLite authority at `.macc/memory.db`. It does not introduce
another session registry or change task completion, review budgets, Git delivery,
model/effort selection, resume arguments or quota handling. An updated adapter
profile can trigger the existing conservative session rotation while preserving
the branch and retained Git work. New services live in
`core/src/o2/`; clients call `o2::actions` and do not implement domain rules.

Memory, automatic context, adaptive compaction and code intelligence are disabled
by default. Existing JSON projects continue to use their existing runner path.
First migrate session authority using the reviewed Sessions operation documented in
[Scoped Sessions](SESSION_STORE.md). Existing SQLite projects then need the
additive O2 schema upgrade to version 2 (including existing P1 version 1 stores):

```sh
macc o2 upgrade
macc o2 upgrade --apply --expected-sha256 <source_sha256-from-preview>
```

Stop coordinator/supervisor and recover outstanding leases before applying. The
upgrade verifies the previewed database fingerprint, makes a consistent SQLite
backup and writes an upgrade report. New SQLite migrations include P1 tables.
`macc save` snapshots these tables with the rest of the memory database; restored
provider receipts may show degraded health until their derived indexes are rebuilt.
See [SQLite snapshots](SAVE_RESTORE.md) for the existing restore boundaries.

## Interactive configuration

Web provides **Ops → Memory, Context, Compaction, Code Intelligence**, and policy
editors at `/config/memory`, `/config/context`, `/config/compaction`,
`/config/code-intelligence`, `/config/o2`. TUI exposes the same domains from
**Sessions → o**, with numbered tabs and a searchable Policies catalog.

Both clients use the canonical revision-checked configuration transaction:
edit → validate/preview → apply. Reset-to-default and remove-overrides are separate
actions. Background refresh preserves drafts; Web policy drafts survive navigation
in per-project session storage. Policy changes activate on the next invocation or
query; deployment is a separate reviewed action. Existing process ownership gates
apply to writes. TUI `j` accepts a typed O2 operation for advanced actions.

The four canonical, optional top-level sections are `memory`, `context_engine`,
`adaptive_compaction`, and `code_intelligence`. `macc o2 status` returns effective
values, defaults, types, ranges, choices and activation timing from the same field
catalog used by both clients. Context Engine requires Memory Ledger enabled.

| Section | Principal defaults |
| --- | --- |
| `memory` | 1,200 body characters; search limit 20; minimum automatic confidence 0.6; provider-note TTL 14 days |
| `context_engine` | 1,200 estimated optional push tokens; 2,000 pull/output tokens; reduction enabled; 65,536 output bytes |
| `adaptive_compaction` | warning/action/guard 0.55/0.70/0.85; minimum 3 turns; observed native compaction budget 2; native auto configuration requires separate opt-in |
| `code_intelligence` | `native_only`; 10,000 tracked files; 262,144 bytes/file; 20 query results; 2,000 estimated output tokens |

## Memory Ledger

SQLite holds canonical checksummed records, normalized evidence, review/conflict
history and a rebuildable FTS5 external-content projection with transactional
triggers. Search restricts project/task/feature/worktree/tool/user scopes **before**
its bounded candidate set. Ranking prefers same-task evidence, constraints and
reviewed decisions, then confidence, with stable tie breaking.

Agent writes are always proposals. Activation requires explicit operator review,
confirmation, a current checksum and validated source or human/review evidence.
A commit alone cannot activate a fact. File evidence carries an exact content hash;
source drift, missing sources and expired provider notes exclude automatic use.
Conflicting claims remain inspectable but both are withheld until resolution.
Stale records can be revalidated with replacement evidence. No memory changes task
completion state. Scope checks organize access within the local project; they are
not a security boundary against another process running as the same OS user.

Content is bounded and scanned for known secrets. Raw runner logs are rejected as
memory; concise sourced lessons are accepted. Source reads reject symlinks,
traversal, secret paths and generated directories. Worktree evidence is restricted
to the same Git common directory. Public search does not persist derived staleness;
automatic dispatch records target-specific snapshot exclusions in the checkpoint manifest.
Only worktree-scoped evidence can acquire persistent source staleness from its own
worktree; divergence in another branch never globally invalidates project facts.

```sh
macc o2 memory-evidence core/src/example.rs
macc o2 memory-search "lease generation" --task TASK-1
macc o2 memory-propose < proposal.json
macc o2 memory-review < reviewed-transition.json
macc o2 fts-rebuild
```

The full tagged JSON contract is available through `macc o2 action` on stdin and
`POST /api/v1/o2/action`; unknown fields are rejected. Use matching scope fields in
`memory_search` / `memory_get` for restricted records.

Agent-facing CLI search/get default to bounded `memory_pull` / `memory_read`
operations. Their complete serialized responses fit `pull_limit_tokens`; oversized
facts become references, and reads expose checksummed, Unicode-safe fragments.
Use `--cursor` / `--offset` for subsequent pages. Compare fragment checksums and
restart a read if evidence changes between requests. O2 CLI responses use compact
JSON plus one newline; the budget estimator measures this exact representation.
TUI/Web may pretty-print the same payload for operator inspection. `--full` retains operator
inspection of complete records. Both clients expose bounded retrieval previews.
Automatic feature scope comes from the selected task’s `feature_id` or string
`feature`; user scope is explicit pull-only because tasks do not establish an
authenticated user identity. TUI Memory uses `f` for conflicts and `v` for a typed
resolution reason, followed by explicit confirmation. TUI/Web offer source capture,
proposal, inspection, reviewed transitions, conflict management and FTS repair.

## Context Engine and output reduction

Checkpoint preparation remains the authority for task, role, worktree, mandatory
PRD acceptance criteria and pinned source hashes. Optional memory is validated,
ranked, deduplicated and budgeted separately. A zero optional budget cannot omit
mandatory PRD or explicit source references. Memory is rendered as lower-authority
cited evidence, never executable instructions.

Every enabled dispatch records a versioned manifest in SQLite and
`.macc/context/bundles/<id>.json`: checkpoint/task/phase, revision and dirty-content
fingerprint, mandatory task, pinned source hashes, selected memory checksums,
selection reasons, exclusions and estimated token use. A content-addressed cache
reuses optional selections only after current source validation; its key includes
scope, mandatory task, phase, policy budget, candidate checksums and source state.
A new checkpoint still gets its own manifest. Raw source remains authoritative.
Optional push selection now measures the complete rendered prompt: JSON fields,
checksums, all references, explanatory framing and the manifest pointer. Empty
selections emit no optional section. Mandatory checkpoint/PRD content remains
separate. The version 3 selection-cache fingerprint rebuilds older estimates
without changing SQLite schema or discarding historical manifests. Per-item usage
estimates cover the serialized item; the bundle total also covers shared framing.

Usage captures the exact checkpoint-linked bundle ID and per-memory/mandatory-PRD
estimates in `context_usage_items`. These estimates do not become provider token
or cost counters. Existing exact/unknown usage semantics remain intact.

`context-list` / `context-get` and the client Context tabs inspect manifests.
`macc o2 reduce test|lint|trace|diff|log` reads output from stdin, reuses existing
summarizers, bounds/redacts the summary without splitting UTF-8 and retains a
private raw artifact reference. The input limit is 8 MiB in CLI/domain calls;
the Web transport retains its existing request size limit.

The existing `Engine::run_skill` path now snapshots reduction policy before
execution and reduces captured non-watch stdout/stderr. An optional
`ToolAdapter::transform_tool_output` hook can transform output; unsupported or
failed hooks use coordinator summarizers. Both streams share the configured
budget, including truncation notices and raw references. Unclassified successful
output stays bounded raw; reducers require explicit `context.summarization`
bundles or an adapter transform. Failed commands bypass semantic reducers and
adapter transforms so stderr such as permission/connection failures remains
visible even without the word “error”. Large failures still respect the budget
and retain a raw pointer. Exit status and private raw logs remain available. Watch streams and opaque JSON/MACC protocol streams
pass through unchanged so usage, quota and completion parsers retain their input.
Provider-internal native tool calls are outside this capture boundary. Token
counts are conservative estimates, separate from provider billing measurements.

## Adapter-declared compaction

Tool profiles declare compaction schema, version pattern, documentation, optional
native configuration and optional exact context/window/count JSON pointers in
`performer.compaction`. Generic code validates and consumes this contract. There
is no tool-name switch in the shared engine or runner.

`macc o2 compaction-probe <tool>` runs bounded `--version` / `--help` checks and
records binary/profile hashes. Before applying a native setting and when inspecting
a previously observed capability, MACC rechecks the bounded read-only `--version`
output against both the exact prior observation and adapter pattern. The full
version output has a SHA-256 fingerprint, separate from the shortened display. This catches
runtime/package upgrades behind unchanged launchers. Drift or probe failure marks
the capability stale and prevents new native settings until an explicit re-probe;
execution retains checkpoint/rotation. The invocation path persists the stale
observation/audit event for the matching profile and executable; read-only inspection
derives its displayed state. An older leased declaration cannot invalidate a newer
operator probe. Legacy probes without a full version fingerprint require a new
explicit probe; they need no database migration.
Version checks reuse the existing three-second/output bound and make no AI call.
This observes version/help compatibility; it does
**not** certify an actual native compression. No paid prompt is used for probing.
Explicit headless compaction remains unsupported unless a future adapter supplies
a verified implementation. Safe checkpoint/rotation remains available.

| Profile | Declared native auto configuration | Unit / boundary |
| --- | --- | --- |
| Codex | `.codex/config.toml`: `model_auto_compact_token_limit` | Explicit token threshold; zero MACC setting preserves provider default. [Official reference](https://developers.openai.com/codex/config-reference/) |
| Claude | `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` | Percent; honors `DISABLE_AUTO_COMPACT`. [Official reference](https://code.claude.com/docs/en/env-vars) |
| Gemini | `.gemini/settings.json`: `model.compressionThreshold` | Fraction. [Official reference](https://geminicli.com/docs/cli/settings/) |
| Vibe | Unsupported configuration capability | Documentation did not establish a verified key; retain checkpoint/rotation. [Official configuration](https://docs.mistral.ai/vibe/code/cli/configuration) |

Native configuration requires `enabled` and `configure_native_auto`, a matching
stored probe, unchanged executable/profile and a live fenced lease. Existing local
settings and explicit environment values are preserved. Version 2 records the
last value of each MACC-owned native setting. Untouched owned values follow later
policy changes; disabling configuration removes only owned values. User-edited
values release ownership. TOML types and unrelated settings survive updates.
Legacy files without ownership receipts remain user-owned until explicitly adopted:
Web Compaction or TUI Compaction `m` previews the setting and exact checksum;
confirmation adopts that one value while the worktree has no active leases.
A changed file or policy invalidates the preview. Adoption writes a receipt;
configuration changes happen on the next fenced invocation.

Missing keys are merged
into the leased worktree's local configuration; they can override inherited global
provider defaults, so opt-in is explicit. No speculative interactive slash command
is passed to headless tools. The event says **configured, compression unobserved**.

Pressure decisions use only declared exact context/window metrics. The shipped
profiles currently declare none: pressure remains unknown and the P0 invocation
budget fallback applies. Billing totals, cached usage, quotas and output tokens
are never treated as context occupancy. In-flight invocations are deferred.
Generation-fenced observed gauges can trigger checkpoint/rotation between calls;
observed compaction counts enforce the configured budget when available. The TUI
and Web distinguish simulations, probes, applied settings and runtime observations.

## Code Intelligence framework

`CodeIntelligenceProvider` is an inventory-registered port with descriptors,
detection, typed queries, lifecycle planning and execution. Unsupported capabilities
are explicit values. The bundled native provider reads bounded current tracked
files and returns literal file/reference matches with file hashes and provenance.
It does not claim parsed symbol, dependency graph or semantic understanding.
Changed files during retrieval are excluded and flagged as snapshot mismatches.

The generic lifecycle manager persists reviewed plans and checks exact plan hash,
project UUID, prior receipt, source revision and dirty source digest before apply.
Plans expose origin, network use and affected paths. Offline mode rejects network
operations. Operations include install, deploy, index, update, rollback, disable,
undeploy and uninstall. Native install records bundled availability; it downloads
nothing. Adapters without a verified lifecycle return Unsupported.

All managed paths must remain below `.macc/code-intelligence/<provider>/` without
symlinks. Removal requires stopped owners/no active leases and removes only
receipted files, preserving memory, Git and unrelated user files. Receipts retain
one rollback predecessor; applied plans replay their original result. Detection
reports missing/corrupt/stale artifacts and version drift, including dirty source
changes. `macc doctor` includes these read-only findings when Code Intelligence
is enabled; it never installs a provider as a repair side effect. Native queries always
read current source even when a cached index is stale. Adaptive routing can try
healthy registered adapters and retains the native fallback with diagnostics.
Cached external queries require a matching provider version, owned artifact hashes
and source snapshot digest at routing time; stale receipts are ineligible.
Every registered provider's query result passes the same response-budget service.
The estimate includes the complete capability envelope, hashes, provenance,
diagnostics and terminating newline. Hits remain whole; oversized results remove
last-ranked hits and explicitly report bounded output. No-hit partial results are
valid at very small budgets. Unsupported reasons are bounded on Unicode boundaries.
Native results obey the contract before and after fallback diagnostics are added.

```sh
macc o2 providers
macc o2 provider-plan native deploy
macc o2 provider-apply <plan-id> <checksum-from-preview>
macc o2 code-query "session_identity" --kind references
```

P2-A adds the optional [managed Graphify adapter](O2_P2_GRAPHIFY.md) through this
same port. P2-B adds Serena symbol navigation and P2-C exposes restricted MCP
queries/proposals. No external backend is installed implicitly.

## Validation

Deterministic regressions cover scope isolation, evidence drift, rejected secrets,
review checksums, conflicts, FTS rebuilding, reviewed upgrades, mandatory PRD
preservation at zero optional budget, content-cache reuse, invocation attribution,
provider lifecycle/removal, dirty-index health, UTF-8 reduction, exact-pressure
rules and declared native configuration in environment/JSON/TOML formats.

The CLI integration suite drives the actual shared Bash runner and session service
with a fake future tool, checking injected memory, mandatory criteria and
cross-task exclusion. Client tests exercise policy preview/CAS, draft retention,
reviewed provider plans and Web ownership/error envelopes. Probe fixtures and
fake providers make no calls to a paid AI service.

```sh
cargo test --workspace --locked
(cd adapters && cargo test --workspace --locked)
make test-tool-runner
cargo clippy --workspace --locked
./scripts/check-ui-tool-transparency.sh
cargo fmt --all -- --check
npm --prefix web run lint
npm --prefix web run test -- --maxWorkers=1 --testTimeout=15000
npm --prefix web run build
```

These checks establish local contracts and regressions. They do not establish
native compression efficacy, third-party installed-version compatibility or
measured token savings on a real project workload.

Web policy preview/apply binds the exact reviewed draft and revision. Late previews
cannot enable Apply for a newer draft; edits made during a save remain unsaved.

P2-B adds [managed Serena](O2_P2_SERENA.md) through the same provider port. It
provides optional Python/Jedi definitions and references with interactive policy
and file scope, isolated runtime ownership, live-source validation and fallback.
The canonical memory/session authorities remain unchanged.

P2-C adds [phase proposals and scoped MCP](O2_P2_MEMORY_MCP.md) through the same
services and common runner. Agent writes remain proposed until operator review.


## Reviewed memory transfer

Selective JSONL/Markdown export and proposed-only import now use the shared operator
actions and guided CLI/TUI/Web workflows. See [Memory transfer](O2_MEMORY_TRANSFER.md).
These operations are distinct from consistent SQLite project save/restore and are
not exposed through the default agent MCP catalog. Real model compatibility remains
an explicit opt-in experiment: [Real tool verification](O2_REAL_TOOL_VERIFICATION.md).
